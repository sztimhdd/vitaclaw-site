# v1.2.1 Production API Runtime Plan

Date: 2026-05-10

## Current Assessment

v1.2 is locally verified, but Aliyun production is still shaped around Caddy
serving the Vite `dist/` directory as static files. That model can serve the
homepage and `/data/agent-news.json`, but it cannot answer
`POST /api/vitaclaw-assistant/chat`.

The repo already contains the minimal Node runtime:

- `server.js` exposes `POST /api/vitaclaw-assistant/chat` and can serve `dist/`.
- `server/vitaclaw-assistant.js` reads
  `docs/product-docs/chunks/vitaclaw-doc-chunks.json` server-side.
- `package.json` includes `npm start` as `node server.js`.

No assistant product behavior change is needed for v1.2.1. The missing piece is
production process management, Caddy routing, and deployment packaging.

## Recommended Architecture

Keep Caddy as the public edge and static file server. Add a local Node process
for API traffic only:

```text
browser
  -> Caddy :80
      /api/* -> reverse_proxy 127.0.0.1:3001 -> node server.js
      /*     -> existing static dist/ hosting
```

Decision: prefer Caddy static `dist/` plus `/api/*` reverse proxy over sending
all traffic to Node.

Rationale:

- Smallest production behavior change from the currently working static site.
- Existing Caddy `/health`, `/healthz`, and static asset behavior can remain.
- Node is responsible only for the server-side assistant API and chunk reads.
- `server.js` still has static fallback, which is useful for local `npm start`
  and harmless behind the `/api/*` proxy.

## systemd Service Proposal

Create `/etc/systemd/system/vitaclaw-site.service`:

```ini
[Unit]
Description=VitaClaw site Node API runtime
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=vitaclaw
Group=vitaclaw
WorkingDirectory=/opt/vitaclaw/control-plane/vitaclaw-site
EnvironmentFile=/etc/vitaclaw/vitaclaw-site.env
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
```

One-time enablement, after explicit production approval:

```bash
systemctl daemon-reload
systemctl enable vitaclaw-site
systemctl start vitaclaw-site
systemctl status vitaclaw-site --no-pager
```

## Caddy Config Proposal

Add the API reverse proxy before the SPA/static fallback in the existing Caddy
site block:

```caddyfile
@vitaclaw_api path /api/*
reverse_proxy @vitaclaw_api 127.0.0.1:3001
```

Full shape, preserving static hosting:

```caddyfile
:80 {
  @vitaclaw_api path /api/*
  reverse_proxy @vitaclaw_api 127.0.0.1:3001

  root * /opt/vitaclaw/control-plane/vitaclaw-site/dist

  respond /health "vitaclaw demo host ok" 200
  respond /healthz "vitaclaw demo host ok" 200

  try_files {path} /index.html
  file_server
}
```

Reload after explicit approval:

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl reload caddy
```

## GitHub Actions Deployment Update

`.github/workflows/deploy.yml` is updated from static-only deployment to API
runtime deployment. The manual workflow now:

1. Builds `dist/`.
2. Backs up current `dist/` and runtime files under `backups/`.
3. Syncs `dist/`.
4. Syncs `server.js`, `server/`, `docs/product-docs/`, `package.json`, and
   `package-lock.json`.
5. Writes `/etc/vitaclaw/vitaclaw-site.env` from GitHub Secrets without printing
   the secret.
6. Runs `npm ci --omit=dev` on Aliyun.
7. Restarts the configured systemd service.
8. Verifies `/health`, `/healthz`, `/api/vitaclaw-assistant/chat`, and
   `/data/agent-news.json`.

The assistant API smoke check posts a blank message. That exercises the route
and should return a local refusal with `usedModel: false`, so it does not call
DeepSeek and does not expose the key.

## Rollback Plan

If static site deployment fails before service restart:

```bash
cd /opt/vitaclaw/control-plane/vitaclaw-site
rm -rf dist
cp -a backups/dist.<timestamp> dist
```

If API runtime deployment fails after files sync:

```bash
cd /opt/vitaclaw/control-plane/vitaclaw-site
tar -xzf backups/runtime.<timestamp>.tgz
npm ci --omit=dev
systemctl restart vitaclaw-site
systemctl is-active --quiet vitaclaw-site
```

If Caddy proxy causes public errors:

1. Remove or comment the `/api/*` reverse proxy block.
2. Run `caddy validate --config /etc/caddy/Caddyfile`.
3. Run `systemctl reload caddy`.
4. Confirm `/health`, `/healthz`, and homepage static assets recover.

This restores the previous static site behavior while leaving v1.2 API
deployment disabled.

## Blockers and Approvals Needed

- Explicit approval is required before any production writes, Caddy reload, or
  service restart.
- One-time Aliyun setup is required for the `vitaclaw` user/group, systemd
  service file, and Caddy proxy block.
- GitHub Variables and Secrets must exist before the workflow can deploy.
- The first GitHub-hosted deploy run is still needed to validate runner and
  server assumptions.

## Residual Risks

- The production Node binary path may differ from `/usr/bin/node`; verify with
  `command -v node` during one-time setup.
- The deploy workflow assumes the deploy user can write `/etc/vitaclaw`, run
  `npm ci --omit=dev`, and restart `vitaclaw-site`.
- Caddy config structure on Aliyun may differ from the full example; apply the
  `/api/*` snippet to the actual active site block.
- If DeepSeek is down or the key is invalid, the server returns extractive
  fallback answers. This is expected v1.2 behavior, not a deployment failure.
